# 승인 대기 제도 폐지 — 학생 자동 승인

## 목표
- 사용자 관리 페이지에서 "승인 대기" 탭과 관련 UI(체크박스 컬럼, 일괄 승인 바)를 제거합니다.
- 새로 들어오는 학생은 별도 승인 없이 즉시 학생 권한을 받습니다.

## 현재 상태 (확인된 사실)
- 역할 데이터: 관리자 1명, 강사 55명, 학생 68명, 승인 대기 7,893명.
- 로그인 시 역할이 없으면 `pending` 역할이 부여되고, 로그인 화면에서 "관리자 승인 대기 중" 안내와 함께 강제 로그아웃됩니다.
- 외부 학생 동기화 웹훅은 계정만 만들고 역할을 주지 않아 결과적으로 승인 대기 상태가 됩니다.

## 작업 내용

### 1. 데이터 정리 (마이그레이션 아님, 데이터 갱신)
- 기존 승인 대기 7,893명에게 학생 역할을 부여하고 `pending` 역할 행을 정리합니다.
  (관리자·강사 역할을 이미 가진 사용자는 그대로 유지)

### 2. 자동 승인 로직
- 로그인 시 역할이 없으면 `pending` 대신 `student` 역할을 부여.
- 외부 학생 동기화 웹훅에서 신규 계정 생성 시 바로 학생 역할 부여.
- 학생 직접 등록 경로도 동일하게 학생 역할 즉시 부여.
- 로그인 화면의 승인 대기 차단 분기 제거.

### 3. 사용자 관리 UI 정리
- "승인 대기" 탭, 탭별 카운트, 선택 체크박스 컬럼, 일괄 승인 바 제거.
- 역할 배지에서 "승인 대기" 표시 제거, 행 작업 버튼에서 "승인 대기로 되돌리기" 제거.
- 탭은 관리자 / 강사 / 학생 3개로 정리(페이지네이션 상태도 3개 기준).

### 4. 서버 함수 정리
- `revertToPending` 제거, `approveUser`·`bulkApproveUsers`는 역할 변경(학생↔강사↔관리자) 용도로만 남기고 pending 삭제 로직 제거.
- 사용자 목록 조회의 `isPending` 기반 제외 필터를 학생 여부 기준으로 단순화.

## 기술 참고
- 수정 파일: `src/routes/admin.users.tsx`, `src/lib/vimeo.functions.ts`, `src/routes/login.tsx`, `src/routes/api/public/webhooks/students-sync.ts`.
- `app_role` enum의 `pending` 값 자체는 다른 정책·데이터 참조 위험 때문에 삭제하지 않고 미사용 상태로 남깁니다.
- 휴원/삭제 학생 필터링 로직은 기존 그대로 유지합니다.
